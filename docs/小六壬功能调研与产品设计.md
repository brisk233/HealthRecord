## 2. 现状盘点：这个功能要插进什么地方

### 2.1 欢洋生活现状（v2.5.0）

- **定位**：双人/家庭生活助手，核心是「一起把日子过好」
- **5 个 tab**：今日 / 菜单 / 健身 / 冰箱 / 我的
- **已有能力**：菜单引擎（冰箱驱动）、营养分析、冰箱库存+保质期、健身课表、三餐+补剂+习惯打卡、家庭记账（含 OCR）、使用建议、云开发双人同步、订阅消息
- **技术栈**：微信原生小程序 + 微信云开发（env `cloudbase-d1glhkgunaf107df5`）；云函数走 `action` 路由（family 是全能型云函数，含 `ensureCollections()` 自动建集合）

**工程约定（设计阶段就要遵守，否则代码必返工）**：
- WXML **禁用**数组/对象字面量（`|| []`）、**禁用**方法调用（`indexOf` 等）→ 复杂计算一律在 js 里预计算成纯布尔/纯字符串
- 全局样式变量在 `app.wxss`（`--brand: #2FB287` 薄荷绿）；组件类 `.card / .hero / .chip / .btn-primary / .btn-ghost / .row`
- 新页面必须在 `app.json` 注册；隐私弹窗组件 `privacy-popup` 需挂到页面
- **QA 铁律**：改完必跑 `node tests/run-tests.js`；UI 行为必须在微信开发者工具模拟器实点验证，不得用单测冒充

### 2.2 「单独加一个菜单」的三种落位

| 落位 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **A. 第 6 个 tab** | tabBar 加「六宫」 | 曝光最高 | tabBar 已有 5 个，拥挤；把玄学放进主 tab **显著放大审核风险** |
| **B. 「我的」页入口行** ✅推荐 | 仿照现有 `goBills / goSuggest` 的 `.row` 入口 | 零 tabBar 改动，风险可控，与记账/建议同级 | 曝光较低 |

## 3. ⚠️ 合规红线（全篇最重要的一节）

### 3.1 微信官方原文（决定性证据）

**证据 1 —— 明文禁止「算命」，而且点名了**

> 出处：《微信小程序平台常见拒绝情形》→ 3. 小程序整体审核规则 → 3.2 页面内容审核规范 → **3.2.4**
> 原文：**「小程序的页面内容中，不能存在测试类内容；示例：算命，抽签，星座运势等。」**
> 链接：https://developers.weixin.qq.com/miniprogram/product/reject.html

注意两点：① 它把「算命」和「抽签」**并列点名**，小六壬两个都占；② 这是**页面内容规范**，约束的是**整个小程序**，不是你新加的那个页面。**一个页面违规，整个欢洋生活可能一起被拒。**

**证据 2 —— 类目库里根本没有占卜这一类**

> 出处：同上 3.1.3
> 原文：**「小程序实际所提供的服务不得属于尚未开放的服务范围。不应超出小程序平台已开放的类目库范围。」**
> 开放类目全表：https://developers.weixin.qq.com/miniprogram/product/material/

我已逐项核对官方开放类目表（非个人主体 22 个大类）。**「文娱」大类下的全部子类目**是：
网络小说 / 学术期刊 / 其他视频 / 视频广场 / 电台 / 音乐 / 有声读物 / 动漫 / 宗教信息

**没有**占卜、命理、玄学、风水、运势、星座中的任何一个。「宗教信息」需宗教事务部门相关资质，且小六壬属民俗术数而非宗教，套不上。**结论：命理占卜属于「尚未开放的服务范围」。**

**证据 3 —— 封建迷信条款**

> 出处：同上 3.2.8.7
> 原文：「小程序内容不能包含煽动民族仇恨、民族歧视、破坏民族团结的内容、破坏国家宗教政策、**宣扬邪教和封建迷信**的」

**证据 4 —— 恐吓性文案会独立触发违规**

> 出处：同上 3.2.3
> 原文：「小程序的页面内容中，存在**对用户产生误导、引发用户恐惧心理**、严重破坏用户体验或损害用户利益的谣言类等内容的，将会被拒绝」

小六壬里「赤口（官非口舌）」「空亡（大凶）」这类传统断辞，若直接照搬（「病者出西方」「恐怕染瘟殃」），**同时踩中 3.2.3 和 3.2.8.7**。

**证据 5 —— 运营规范直接点名「AI算命」（本次调研最致命的一条）**

> 出处：《微信小程序平台运营规范》**5.12.15**
> 原文：不允许「……包括但不限于**人像评分、AI算命**等」
> 处理：**封禁能力直至封号**
> 链接：https://developers.weixin.qq.com/miniprogram/product/

**这不是「算命」三个字，是官方原文里明明白白写着的「AI算命」。** 你想做的正是「AI 算卦」——这条条款几乎是逐字针对。我第一版报告只查了《常见拒绝情形》就下了结论，漏了这条，现补上。

**证据 6 —— 虚假迷信条款**

> 出处：同上 **6.4.5**
> 原文：「发布封建迷信，恐吓诅咒挂钩的内容」→ 限制功能直至**封号**

**证据 7 —— 处罚是「整个主体」级别，不是「这个功能」级别**

| 条款 | 要点 | 后果 |
| --- | --- | --- |
| **5.7 类目不符** | 按违规程度处理 | **封禁能力直至下架** ← 是整个小程序 |
| **5.19 对抗审核** | 不得「绕开、规避或对抗」审核 | **永久下架，且腾讯有权拒绝再为相关主体提供服务**；**同主体／关联主体累计处罚** |
| **3.1.2** | 所有服务类目功能必须在**首页 2 次点击内可达** | **做成 tab ＝ 主动摆到审核员眼前** |
| **5.13 虚拟支付** | 不得引导至 app、公众号、h5、个人号、网站完成支付 | **堵死「走公众号二维码收款」这条路** |
| **5.18 / 5.18.2** | 必须调用内容安全检测接口，并**点名「算命类 UGC 小程序」** | AI 生成文本必须过 `security.msgSecCheck` |
| **四、投诉与处罚规范** | 多次整改不合规 | 腾讯有权**永久关闭申诉渠道** |

**真实驳回案例（8 例，均有 URL）——最有说服力的一条：**

> 一位开发者把「八字合图」小程序先后换了 **工具>图片、工具>信息查询、生活服务>休闲娱乐、文娱>资讯** 四个类目提交，**全部被拒**。
> 官方回复：「小程序实际所提供的服务属于**尚未开放的服务类目：付费算命**。」
> 唯一的出路被明确告知：**「请重新定位小程序功能」**。
> 链接：https://wxopen.club/topic/5e3d2b023b620ac19a798d86

**⚠️ 关键事实：未检索到任何「算命类小程序申诉成功并上线」的公开案例。** 对「为什么别人能过我通不过」，官方的回复是「建议你线上提交投诉」——**「友商还活着」不是合规依据**。

**2024-08-01 微信公众平台运营中心专项公告**：明确打击「封建迷信风气，借宗教、风水、运势等噱头敛财或博取关注」，违规案例包括「**不正当地采集用户个人隐私信息，包括但不限于：姓名、生辰八字、面/手相**」。

**如果坚持用 LLM，还有一整套独立合规要求（当前完全没有）**：
- 需补 **深度合成-AI问答** 类目
- 需 **《互联网信息服务算法备案》（生成合成类）**
- 需按《人工智能生成合成内容标识办法》（**2025-09-01 已施行**）做 **AI 生成内容显著标注**
- 接入 `security.msgSecCheck` 是**必要非充分**条件

### 3.2 连带风险（比「这个页面被拒」更严重）

| 风险 | 依据 | 后果 |
| --- | --- | --- |
| **类目不符** | 《运营规范》5.7 类目不符行为 | 警告 → 限制功能 → 下架 |
| **整个小程序被拒** | 3.2 是整体页面内容规范 | 已上线的家庭助手一起卡审核 |
| **已有功能被牵连** | 审核按小程序整体判断 | 记账 OCR、云同步等正常功能可能被质疑 |
| **生成式 AI 额外合规** | 《生成式人工智能服务管理暂行办法》 | AI 生成解读若面向公众，可能触发备案/资质要求 |
| **诱导分享** | 3.2.1 | 若做「分享结果海报解锁」，直接违规 |
| **无实质服务内容** | 《运营规范》5.29 | 纯娱乐抽签若被判定为无实质服务，也会被拒 |

### 3.3 关键区分：自用 ≠ 发布

这一点决定风险等级，必须讲清楚：

- **只你和家人自用**（家庭码内的体验版、不给外部用户）：**审核不介入**，风险几乎为零，可以直接做完整小六壬，包括传统断辞。
- **要正式发布给所有用户**（提交审核、上架）：**上述红线全部生效**，必须做合规改造。

**所以第一个要问你的问题是：这个功能是自用玩具，还是要给所有用户用？** 两种答案对应完全不同的做法。

### 3.4 行业实践者的一致结论（旁证）

我另外查了小程序外包行业对这个问题的公开表态，结论和官方规范完全吻合：

> 「大家记住，以平台最新审核规范为准，**微信小程序现在根本没有"算命"、"占卜"这种类目**。你想上线，就必须懂包装……代码里**绝对不能出现"破财、血光之灾、改运、做法事"这些敏感词**，得全部替换成"性格潜能分析、国学文化探讨、环境心理学"。」
> —— [开发一个算命小程序需要多少钱？先别掏钱，看微信给不给过审](https://www.ltzsw.com/xiaochengxukaifang/8070.html)

> 「即使你的代码写好了，提交给微信审核，这种涉及玄学测算类的小程序，**99% 的概率是过不了审的**。运气好可能让你改几次，**运气不好直接永久封禁主体账号**。」
> —— [八字算命小程序能不能开发？](http://www.055188.net/News/6977/)

> 「去年有个做国学馆的老板，自己找大学生兼职花了五万把代码敲完了，兴冲冲去提审。结果**卡在类目选择上，直接被驳回，理由是涉嫌封建迷信**。」

**另外两个必须知道的硬约束**：

1. **iOS 端严禁虚拟支付**——微信规范写死：iOS 小程序不得提供任何形式的虚拟支付。你若在 iPhone 上放「9.9 元解锁详细解读」，审核必挂；即使绕过审核上线，被系统扫到会**永久封禁支付能力**。（这也是为什么我在 §6.6 把「付费/会员」直接标为禁止项，不只是合规问题，是技术上就走不通。）
2. **主体账号风险**——违规不只是「这个小程序下架」，可能上升到**主体信用**。对一个已经在运营的账号来说，这个代价远大于新功能带来的收益。

### 3.5 ⚠️ 我对本报告结论的修订（必读）

补完上述证据后，**我必须撤回第一版给出的推荐路径**——原推荐是「路径 B：合规改造后内置」。撤回理由：

**理由 1：改名/包装无法规避。**

我原以为把「算卦」改造成「决策辅助」就能合规。但 3.2.4 的判定标准是**页面实际提供什么服务，不是文案怎么写**。我设计的「六宫裁判」在审核员眼里，就是**一个有掌诀动画、六个卦名、输出裁决结果的抽签程序**——这恰恰是 3.2.4 点名的「算命，抽签」。**换个说法不改变它的实际形态。**

**理由 2：风险收益比严重不成立。**

| | 收益 | 代价 |
| --- | --- | --- |
| 最坏情况 | 一个趣味功能带来的活跃度 | **整个欢洋生活被下架**（5.7）+ **主体被拉黑、关联小程序连坐**（5.19）+ **申诉渠道永久关闭** + **封号**（5.12.15 / 6.4.5） |

你现在的 App 已经跑到 v2.5.0，里面有**真实的双人档案、冰箱库存、账单记录、打卡历史**。拿这些去换一个娱乐功能，**哪怕成功概率有 80%，这个赌注也不该下**。而官方条款是明文点名，成功概率远不到 80%。

**理由 3：连「自用」都未必安全。**

§3.3 说自用不涉及审核——**这是对的，但只在你永远不提交审核的前提下成立**。而你的手册里第 4 周的任务就是「真机测试 + 体验版上线」，这个功能大概率会被一起带上线。

**修订后的三个方案（见 §10 决策）：**
- **方案 A（新推荐）**：**留内核，去玄学** —— 在欢洋生活里做「双人决策 + 情绪提示」，但**页面里完全不出现六宫、掐指、卦、签、吉凶、运势**。保住约 80% 用户价值，合规风险≈0。
- **方案 B**：不做。最稳基线。
- **方案 C**：独立载体做完整小六壬（自有 App／独立站）。⚠️ 小游戏、H5 外链、公众号**三条路已被官方条款堵死**。

## 4. 需求拆解：用户真正要的是什么

### 4.1 市场数据（第三方来源，非我编造）

- **艾媒咨询《2025-2029 年中国情绪经济消费趋势洞察报告》**：2024 年中国情绪经济市场规模 23077.67 亿元，预计 2029 年突破 4.5 万亿元；**18.29%** 的消费者喜爱「玄学与好运经济」消费，**高于**「虚拟情感陪伴」的 16.86%。
- **后浪研究所《2025 年轻人玄学消费报告》**：18-30 岁年轻人中 **60% 体验过「AI 算命」**。他们最关心的**不是爱情（仅 49.6%）**，而是**事业（76.5%）和财运（74.9%）**。
- **用户原话**（报道中引用的真实用户表述）：
  - 「**很多时候，我只是想听我想听到的答案**，这样才能让我当前糟糕的现状有了发泄的出口。」
  - 「算完后觉得**似乎真有一位占卜师在劝慰自己**……这让她在患得患失中**有找到依据的感觉**。」

> 来源：[澎湃·赛博算命"拿捏"年轻人](https://m.thepaper.cn/newsDetail_forward_31337239)、[红网·"AI算命"的预测里，谁在掌控命运？](https://moment.rednet.cn/pc/content/646047/91/15751917.html)

**这三条数据直接改写了产品定义**：

1. **动机是情绪价值，不是预测准确度。** 用户要的是「被劝慰」「有个依据」「情绪出口」。所以**产品成败在于文案的共情力和行动指引力，而不是算法的神秘感**。
2. **最热的需求（事业/财运）恰恰最违规。** 预测事业财运 = 典型算命内容，必被拒。而**决策辅助、情绪安抚、伴侣互动**这三块可以合规做——它们是需求的下半部分，但正是**可做**的部分。
3. **行业已有明确污点**：央视曝光过「AI 相面」小程序窃取手机照片和通讯录；付费套路（9.9 元引流 → 累计 52.4 元）；拉人头代理游走传销边缘。**我们必须在这三点上做出明确的对立选择**，否则会被用户默认归入「骗子那一类」。

**还有两条反直觉的画像数据，直接决定我们的设计取舍：**

- **用户不是「迷信的人」**：一线/新一线城市占近 80%，金融、互联网、科研等**理性职业占比很高**（澎湃 SEC Media Lab）。用户自己也知道这是消遣——所以产品**不需要装神弄鬼**，反而应该坦荡。
- **容忍度是不对称的**（这条最关键）：
  - 对「**算不准**」→ 容忍度**很高**（「当个消遣」「比豆包有趣」）
  - 对「**被当韭菜**」「**被制造焦虑**」→ 容忍度**极低**，且会直接转化成差评和举报

  → **风险不在玄学本身，在商业设计的吃相。** 我们本来就不打算收费、不打算做付费墙，所以这个最大的行业风险对我们是天然免疫的——但必须**在产品里明说出来**，让用户一眼看出我们和那些产品不是一类。

### 4.2 JTBD：用户「雇佣」这个功能，是要完成什么任务？

不要问「用户想要什么功能」，要问「用户在什么情境下，会把这个功能拉进来替自己干活」。

**主任务（功能层）**
> 当我**反复权衡同一件事、信息其实已经够了、但就是拍不下板**的时候，
> 我想要**一个不带利害关系的外部信号，帮我终结思考并给出一个能立刻执行的下一步**，
> 这样我就能**从「悬着」的状态里出来，把时间拿去做事，而不是继续想**。

**情绪任务**
> 当我焦虑、患得患失、对未来没底的时候，
> 我想要**一个把我此刻处境说清楚、并告诉我「你还能做点什么」的东西**，
> 这样我就能**感到被理解、感到主动权还在自己手里**，而不是被命运摆布。

**社交任务（本 App 的独家优势）**
> 当我和另一半为「今天吃什么 / 谁来洗碗 / 周末去哪」僵住的时候，
> 我想要**一个两个人都服气、还觉得好玩的第三方裁判**，
> 这样我们就能**不伤和气地把事情定了，还多一个共同话题**。

### 4.3 用户不要什么（反向需求，同样重要）

- ❌ 不要被吓到（「大凶」「灾殃」）→ 既违规又直接流失
- ❌ 不要被收智商税（付费解锁完整版）→ 行业污点 + 虚拟支付违规
- ❌ 不要笼统套话（「太模板化了」是竞品最高频差评）
- ❌ 不要被要求分享才能看结果 → 诱导分享违规
- ❌ 不要泄露隐私（生辰八字、照片、通讯录一律不要）

## 5. 认知科学依据：为什么「随机决策工具」是真有用的

这是把「算卦」合法化、同时**不欺骗用户**的关键。随机决策工具的价值有扎实的学术支持：

**研究 1：硬币翻转会暴露你真实的偏好**
> Jaffé, M. E., & Greifeneder, R. (2021). *This outcome feels right! Subjective evaluations of coin flip outcomes reflect previously stated preferences.* **PLoS ONE**, 16(7), e0253751.
> 结论：人们对硬币结果产生的**情绪反应，能有效反映他们此前已经表达的偏好**。
> https://pmc.ncbi.nlm.nih.gov/articles/PMC8253383/

**研究 2：硬币翻转减少决策中的信息搜寻**
> *Toss and turn or toss and stop? A coin flip reduces the need for information in decision-making.* **Journal of Experimental Social Psychology** (2019).
> https://www.sciencedirect.com/science/article/abs/pii/S0022103118303950

**这说明什么（也是我们诚实的卖点）：**

1. **机制不是「预测未来」，而是「照见你已经想要什么」。** 硬币说 A，你心里一沉——你就知道了你其实想要 B。**小六壬六宫在这里扮演同一角色，只是外壳更有文化质感、解读维度更丰富。**
2. **真正的价值是「停止搜寻」。** 纠结的本质是无限地找理由。一个外部信号能合法地叫停这个过程——这是**省时间**，是真实效用。
3. **所以我们可以理直气壮地写「这不是预测，是帮你看清自己」**，而不是心虚地写「仅供娱乐」。前者是诚实的产品说明，后者是免责声明式的敷衍，用户能分辨。

**另外两个心理学机制可以正面利用：**
- **巴纳姆效应**（笼统描述被当成精准）：竞品用它行骗，我们**反过来用**——把描述写得**具体到行动**（「今天下午 3 点前把最关键的那封邮件发出去」），而非笼统（「你最近会遇到贵人」）。具体化会破坏巴纳姆效应的欺骗性，却**提升真实有用性**。
- **反刍思维打断**：焦虑的核心是思维反刍。一个结构化外部框架（六宫 = 六种审视视角）能把「我完蛋了」转成「这件事现在卡在哪一步」，有认知行为疗法（CBT）的味道。

## 6. 产品设计方案

### 6.1 逆向工作法：先写「发布时的新闻稿」

> **【欢洋生活 2.6.0】新增「掌中决」：两个人的选择困难，交给六宫**
>
> 今天，欢洋生活上线新功能「掌中决」。它源于一个很小但每天都在发生的麻烦：**两个人在一起，最难的往往不是大事，而是「今天吃什么」「谁洗碗」「周末去哪」。**
>
> 「掌中决」把中国传统的**小六壬六宫**——大安、留连、速喜、赤口、小吉、空亡——变成了一套轻巧的**决策提示**：
> - **纠结时**：输入你正在权衡的两三个选项，掐指一算，六宫给你一个结果，**并附上一句「为什么现在适合这么选」的行动提示**。
> - **想不清楚时**：写下一件让你悬着的事，抽一宫，得到一张**提示卡**——不是预言，而是「这件事现在处于什么局面、你能做的下一步是什么」。
> - **想了解时**：「六宫小识」用 3 分钟讲清这套民俗文化的来龙去脉，附掌诀图。
>
> 我们**不做吉凶预测，不做付费解锁，不要你的生辰八字**。「掌中决」的价值不是告诉你未来会发生什么，而是**帮你停止内耗、把决定做掉**——有研究显示，随机的决策信号之所以有用，是因为它会**照出你心里其实已经倾向的那个答案**。
>
> 两个人一起用它做决定，比一个人纠结快得多，也好玩得多。

**如果这段新闻稿读起来让你觉得丢人，那这个产品定义就是错的。** 我的判断是：它比「AI 算卦」更值得发。

### 6.2 机会解决方案树（Opportunity Solution Tree）

```
目标（Outcome）：让双人日常决策更快、更少摩擦，并提高 App 的日活回访
│
├─ 机会 1：两人为小事僵持（今天吃什么/谁洗碗/去哪玩）
│   ├─ 方案 1a：「六宫裁判」——输入选项，出结果 + 理由        ✅ 最高优先
│   ├─ 方案 1b：与冰箱/菜单数据联动，先给 2 个能做的再裁决
│   └─ 方案 1c：伴侣双方各抽一次，比对结果（互动玩法）
│
├─ 机会 2：一个人对某件事悬着、反复想
│   ├─ 方案 2a：「一念」提示卡——写下一件事，抽一宫，得行动提示   ✅ 高优先
│   ├─ 方案 2b：历史记录 → 回看「当时抽到什么、后来怎么做了」的自省闭环
│   └─ 方案 2c：把「宜/忌」转成当日待办，挂进今日页
│
├─ 机会 3：对这套民俗文化好奇，但没有了解渠道
│   └─ 方案 3a：「六宫小识」科普页 + 掌诀动画                ✅ 零风险，可先做
│
└─ 机会 4：想和朋友/伴侣有共同话题
    ├─ 方案 4a：结果卡片（仅保存到相册，不强制分享）          ⚠️ 分享必须自愿、无奖励
    └─ 方案 4b：两人「今日各抽一宫」→ 今日页并排展示
```

### 6.3 产品定位：三个层次（按风险从低到高）

| 层次 | 名称 | 做什么 | 合规风险 | 建议 |
| --- | --- | --- | --- | --- |
| **L1** | **六宫裁判** | 情侣/双人选择困难决策器。输入选项 → 掐指一算 → 出结果 + 一句行动提示 | **极低**（本质是随机选择器） | ✅ 主打，先做 |
| **L2** | **一念 · 提示卡** | 写下一件纠结的事 → 抽一宫 → 得处境描述 + 下一步建议。**明确标注「随机提示，非预测」** | **中**（措辞必须严格，禁止吉凶/预言词） | ✅ 做，但文案要过审校 |
| **L3** | **六宫小识** | 小六壬文化科普：由来、六宫含义、掌诀图、历史 | **极低**（纯知识内容） | ✅ 做，为整个功能提供文化正当性 |
| ~~L4~~ | ~~AI 算卦 / 吉凶预测~~ | ~~输入生辰八字/随机数 → 预测事业财运姻缘~~ | **致命** | ❌ 不做 |

**贯穿三层的 5 条设计原则**：
1. **把「预测」全换成「提示」**：不说「你会……」，只说「这件事现在……，你可以……」
2. **把「吉凶」全换成「情境」**：不写「大凶」，写「当前格局：事情有明显阻力，先排查卡点」。**保留六宫名字与文化意涵，换掉断辞的恐吓性**
3. **把「命定」全换成「行动」**：每次输出的最后一句必须是一个**具体的、今天就能做的动作**
4. **零隐私**：不要生辰、不要照片、不要通讯录、不要位置——这是与行业污点的第一道切割
5. **零付费、零诱导分享**——第二、第三道切割

### 6.4 核心交互流程（L1 六宫裁判）

```
[入口] 今日页卡片「今天听谁的」/ 我的页「🔮 掌中决」
   ↓
[输入] 你在纠结什么？
   ○ 预设场景（今天吃什么 / 谁做家务 / 周末去哪 / 买不买 / 自定义）
   ○ 填 2~3 个选项
   ↓
[起课] 「掐指一算」→ 掌诀动画（六宫在指节上依次亮起，约 1.2s）
   ↓
[结果] 大卡片：
   ┌──────────────────────────────┐
   │  速喜                          │
   │  火 · 南方 · 宜快不宜慢          │
   │                                │
   │  【结果】就去吃火锅 🍲           │
   │                                │
   │  【为什么】这件事现在处在「速喜」   │
   │  的格局：时机是热的，再拖下去反而   │
   │  会凉。既然两个选项你都还行，就选   │
   │  那个让你现在更兴奋的。            │
   │                                │
   │  【下一步】现在出发，别改。        │
   └──────────────────────────────┘
   ↓
[收尾] ○ 就这么定了    ○ 再算一次（同日同题限 3 次，防沉迷）
[沉淀] 历史记录（本地）→ 我的页可回看
```

**L2 一念（自省）流程**：写下一件纠结的事（一句话）→ 抽一宫 → 输出「处境描述 + 一个你可以控制的变量 + 今天能做的一个动作」，并**始终显示一行**：「这是一次随机提示，帮你换个角度看问题，不是预测。」

### 6.5 Kano 模型：功能属性分类

| 类别 | 属性 | 处理 |
| --- | --- | --- |
| **基本型**（没有就不满意） | 结果即时、随机公平（不能被怀疑动手脚）、能重来、无隐私索取 | 必须做 |
| **期望型**（越多越满意） | 解读文案质量高、有历史记录、掌诀动画质感、界面好看 | 重点投入 |
| **兴奋型**（超预期） | 与冰箱/菜单数据联动（「冰箱里这些菜，挑一道」）、伴侣双方各抽一宫并排展示、结果卡片可存相册 | 差异化亮点 |
| **无差异** | 复杂参数设置、多流派切换、真太阳时校正 | 砍掉 |
| **反向**（做了会掉分） | 吉凶断言、恐吓文案、付费解锁、强制分享、索取生辰/照片 | **明令禁止** |

| AI 生成的个性化解读 | 高 | 中 | 低 | 高 | **低**（见 §7.4） |
| 付费 / 会员 | — | — | — | — | **禁止** |

### 6.7 指标（HEART）与留存（Hook）

**HEART**
- **Happiness**：结果页放「这个提示对你有用吗？」两键反馈（有用 / 不太准）→ 文案迭代的唯一数据源
- **Engagement**：人均周使用次数（目标 ≥ 3 次/周，情侣场景天然高频）
- **Adoption**：入口点击率 / 首次完成率
- **Retention**：7 日回访率（关键指标）
- **Task Success**：**「就这么定了」点击率**——最重要，它证明功能真的帮人做了决定，而不是抽完就走

**Hook 模型**
- **Trigger**：外部——今日页「今天吃什么」的纠结时刻；内部——「算了抽一下」的习惯
- **Action**：极简，输入到结果 ≤ 3 步
- **Variable Reward**：六宫随机 + 文案每次不同
- **Investment**：写下真实纠结的事 + 历史记录 → 投入越多，越会回来看「上次那件事后来怎样了」

### 6.8 文案样例：这里才是决定成败的地方

调研数据显示用户要的是「被劝慰」「有个依据」，**不是算法神秘感**。所以真正决定这个产品好不好用的，是文案。下面给三组完整样例，让你判断这个方向做出来到底是什么手感。

**样例 1（L1 六宫裁判）· 场景：今天吃什么 · 落在「速喜」**

> **速喜** · 火 · 南方 · 宜快不宜慢
>
> **结果**：就去吃火锅 🍲
>
> **为什么**：这件事现在处在「速喜」的格局——时机是热的，你越权衡它越凉。你列的两个选项其实都行，说明这不是一道需要想清楚的题，而是一道需要拍板的题。
>
> **下一步**：现在出发，路上别再改。

**样例 2（L2 一念）· 场景：纠结要不要接一个新项目 · 落在「留连」**

> **留连** · 水 · 南方 · 事有反复，宜缓不宜急
>
> **你写的**：要不要接这个新项目
>
> **现在的局面**：这件事处在「留连」——它不是「不行」，而是「还没到时候」。你反复想了很多天却没有进展，通常不是因为你缺决心，而是因为**有一个具体的信息你还没拿到**。
>
> **你能控制的那个变量**：把「要不要接」换成「我需要知道哪一件事才能决定」。多数时候答案是一个数字（预算/工期）或一句对方没说清的话。
>
> **今天能做的一件事**：把那个问题直接问出去。今晚之前。
>
> *这是一次随机提示，帮你换个角度看问题，不是预测。*

**样例 3 · 场景：丢了一件东西（你原始设想里的场景）· 落在「空亡」**

> ❌ **原版传统断辞会这么写**：「空亡事不祥……失物寻不见，官事有刑伤，病人逢暗鬼」——**直接踩中 3.2.3（引发恐惧）和 3.2.8.7（封建迷信），必被拒。**
>
> ✅ **合规改写**：
> **空亡** · 土 · 西南 · 信息不足，先把信息补齐
>
> **现在的局面**：这件事处在「空亡」——不是你找不到，而是**你手上的线索还不够定位它**。这个格局提示的是「方向不对，努力白费」，硬找会更烦躁。
>
> **下一步（三选一，挑一个现在就做）**：
> ① 在纸上写下**你最后一次确定见到它**的时间、地点、当时手上还在做什么；
> ② 从这个场景出发，按「最可能 → 次可能」顺序**只排查两个地方**，别全屋翻；
> ③ 如果 24 小时内仍没有，就**先给它一个结论**（补办/再买），把注意力收回来——这是「空亡」真正想提示的事：**有些事放下比找回更划算。**
>
> *这是一次随机提示，帮你换个角度看问题，不是预测。*

**从这三组样例可以看出什么**

| 传统小六壬的写法 | 我们改写后的规则 |
| --- | --- |
| 「失物在坤方」 | 「写下最后一次见到它的场景，按顺序排查两个地方」——**给方法而不是给方位** |
| 「大凶」「灾殃」 | 「这个格局提示的是方向不对」——**给情境而不是给吉凶** |
| 「你最近会遇到贵人」 | 「把那个问题今晚之前问出去」——**给动作而不是给预言** |
| 结果页戛然而止 | 永远以「今天能做的一件事」收尾——**这是留存的关键，也是产品价值所在** |

**这三组样例也直接回答了「AI 能不能写好」**：能，但没必要——48 段这样的文案，人工打磨一遍的成本，远低于接大模型 + 做内容安全 + 建评测集的成本。**而且人工写的永远不会违规。**

### 6.9 最大的市场空白，恰好只有你能填 ⭐

子代理深挖 17+ 款竞品后，发现了一个**明确且无人占据**的空白：

> **没有任何一款产品把用户真实的生活数据（天气/日程/消费/健康）接进解读；也没有任何一款产品把「建议」变成待办、提醒和回访闭环。**

而这两件事，**欢洋生活已经全部具备**：

| 竞品要从零开始建 | 欢洋生活已经有了 |
| --- | --- |
| 用户日程 | 今日页（三餐打卡、习惯打卡、训练卡） |
| 用户消费 | 家庭记账（含 OCR 账单导入） |
| 饮食 / 健康数据 | 冰箱库存 + 保质期 + 菜单引擎 + 营养分析 |
| 主动触达能力 | 订阅消息（remind 云函数，**已部署可用**） |
| 双人关系数据 | 家庭码 + 双人档案 |

**由此得到一个竞品抄不走的形态：**

```
起课 → 断语 → 结合你的真实生活数据 → 1~3 件可做的事 → 加进今日页待办 → 3 天后回访
```

举几个**只有你能做**的例子：

- **「今天吃什么」起课 → 直接读冰箱库存**，只在「现在真能做的菜」里裁决。用户不用手输选项——比所有竞品都少一步。
- **「留连」提示「有个信息你还没拿到」→ 结合记账数据**，可能正是「那笔预算还没确认」。
- **抽到「宜：把拖着的事推进」→ 一键加进今日页习惯流**，从「看过」变成「会做」。
- **3 天后 remind 云函数推送**：「上次那件事，后来怎样了？」→ **完整闭环**。竞品全部停留在「看完就结束」，这正是月见用户抱怨的「指导性不够」。

> **这是本次调研最有价值的一条结论**：你的护城河**不是小六壬算法**（开源实现现成，见 §4.4），而是**这个 App 已经握在手里的生活数据 + 双人关系**。竞品要做这件事，得先花一年建一个生活助手——而你已经建好了。

**传播上还有一个低成本高回报的空白**：
> 小六壬目前**没有任何产品做出好看的分享卡**。而「可晒的结果卡」是这类产品被验证过的传播方式（「人生 K 线」单条推文 300 万浏览；合盘分数）。⚠️ 但分享必须**完全自愿、零奖励**，否则触发诱导分享（§3.2）。

## 7. 技术实现方案

### 7.1 结论：v1 不要用 AI

三条理由都是硬的：
1. **算法 100% 可本地计算**——六宫推演是纯取余运算，不需要服务器、零延迟、零成本
2. **文案库本地化质量更可控**——6 宫 × 约 8 个场景 = 48 段文案，人工打磨一遍就能达到「比 AI 好」的水平，而且**永远不会输出违规内容**
3. **接大模型的合规成本远超收益**——需处理内容安全检测（`security.msgSecCheck`）、生成式 AI 相关合规，以及流式输出/超时等工程问题

**AI 是 v2 的增强项，不是 v1 的前提。**

**起课算法（两种，都要实现）**

```js
// 六宫循环顺序：大安 → 留连 → 速喜 → 赤口 → 小吉 → 空亡 → (回大安)

// ① 传统时间起课：寅上起月，月上起日，日上起时
//    m = 农历月(1-12)，d = 农历日(1-30)，h = 时辰序号(子=1 … 亥=12)
function divineByTime(m, d, h) {
  const monthIdx = (m - 1) % 6;              // 从大安起正月
  const dayIdx   = (monthIdx + d - 1) % 6;   // 从月宫起初一
  const hourIdx  = (dayIdx + h - 1) % 6;     // 从日宫起子时
  return { month: monthIdx, day: dayIdx, hour: hourIdx };
}

// ② 随机数起课（报三数 n1 n2 n3，正整数）
//    取余天然处理「余数为 0」：((n-1) % 6) 永远落在 0..5
function divineByNumbers(n1, n2, n3) {
  const a = (n1 - 1) % 6;
  const b = (a + n2 - 1) % 6;
  const c = (b + n3 - 1) % 6;
  return { month: a, day: b, hour: c };
}
```

**时辰对照**（时辰序号 → 现代时间）：
子 23-1 ｜ 丑 1-3 ｜ 寅 3-5 ｜ 卯 5-7 ｜ 辰 7-9 ｜ 巳 9-11 ｜ 午 11-13 ｜ 未 13-15 ｜ 申 15-17 ｜ 酉 17-19 ｜ 戌 19-21 ｜ 亥 21-23

> ✅ **算法已验证（2026-09 专项调研交叉核实）**：上面的公式与《玉匣记》原文推算一致。验证案例：**三月初五辰时 → 小吉**（与古籍原文例子吻合）。
>
> ⚠️ **网上流传一个错误写法**：「(月+日+时) mod 6，余 0 当 6」。同一输入会得到**不同结果**（三月初五辰时错算成「大安」）。代表错误来源是某腾讯云社区的 Java 实现文章。**实现时务必用上面的公式，不要用「三数相加取余」。**
>
> ⚠️ **两个实现陷阱，务必避开：**
>
> **1. 农历转换**：传统时间起课需要**农历**。小程序端没有内置农历转换，需引入农历算法（约 100 行纯函数，无依赖）。**v1 建议只做「随机数起课」**（这也恰好是最合规、零隐私的起课方式），农历起课放 v2。
>
> **2. 子时跨日（竞品真实翻车点）**：子时是 **23:00–01:00，跨过午夜**，传统上有「早子时 / 晚子时」之分，不同流派处理方式不同。竞品「掐指一算」的用户差评里**明确有「子时排盘错误」**——被用户抓到并写进评论区、直接拉低评分。若做时间起课，必须**明确选定一种处理方式并在界面上说明依据**；若只做随机数起课，则天然规避。

| 方案 | 做法 | 坑 |
| --- | --- | --- |
| **云函数代理**（推荐） | 小程序 → `family` 云函数 → 腾讯混元/DeepSeek API | API Key 放云函数环境变量，**绝不能进代码仓库**；需处理 60s 超时 |
| `wx.cloud.extend.AI` | 云开发内置 AI，免 Key 管理 | 模型选择受限；流式输出在小程序端有坑 |

**无论哪种，都必须做**：
1. **内容安全检测**：AI 输出必须过 `security.msgSecCheck`（云函数端调用），防止生成违规内容——这是《常见拒绝情形》3.2.11（服务提供者必须提供过滤不当内容的措施）的硬要求
2. **Prompt 强约束**：系统提示词锁定为「决策提示」而非「命运预测」，禁止吉凶/疾病/死亡/财运承诺类输出
3. **AI Evals**：建 50 条测试集（覆盖六宫 × 各场景 × 边界输入），每次改 Prompt 都跑，检查违规词与行动建议质量
4. **降级**：AI 超时/失败时回落到本地模板文案——**本地模板永远是兜底，这也是为什么 v1 必须先做本地库**

- 若做「结果卡片存相册」→ 需 `wx.saveImageToPhotosAlbum`，属**隐私接口**，README 的隐私指引需补充「相册（仅保存）」用途
