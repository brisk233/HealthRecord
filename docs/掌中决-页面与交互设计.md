## 2. 主页面结构：单页多状态（不跳页）

**关键决策：主页面内部用状态切换，不跳转新页面。** 输入到结果全程一屏完成，减少跳转、保持"一口气算完"的流畅感。

底部固定三个入口行（寻物 / 走向 / 科普）。**扩展被构建脚本移除后，这两行自动消失，页面结构不变**——这是选择「入口行」而不是「顶部 tab」的原因。

## 10. 走向页 · 互动解读与 AI 通道（v2 实现）

### 10.1 交互流程（替代原来「直接甩三宫断辞」）

```
落宫动画结束
  → 先问一句「你最想先弄清楚哪一点？」（能不能成 / 大概什么时候 / 我该主动还是等 / 有没有我没想到的）
  → 一句话白话结论（随关注点变化）
  → 三层来龙去脉：默认只展开「起」，点一层开一层，可「继续展开下一层」
  → 接下来怎么做：3 条可执行建议 + 「今天只做一件事」
  → 还想问什么：4 条追问，点开才显示回答
  → 应期 + 提示语 + AI 标注
```

页面方法：`pickFocus / toggleLayer / nextLayer / toggleFollowup / regenerate / useLocal`。

### 10.2 两层解读：本地引擎 + AI 增强

| 层 | 文件 | 特点 |
| --- | --- | --- |
| 本地解读（兜底） | `data/zzj-read.js` | 纯本地、零外传、即时出结果；4 关注点 × 6 情境词全组合有文案 |
| AI 解读（增强） | 云函数 `action: reading` → DeepSeek | 本地先出，AI 异步替换；失败/超时/不合规 → 保持本地并提示「AI 暂不可用」 |

页面按钮：「重新生成 AI 解读」「换回本地解读」——用户可以随时退回纯本地路径。

### 10.3 隐私与安全约定（改 AI 相关代码必须遵守）

1. **只上送**：问题文本（≤60 字）+ 三宫情境词 + 关注点；**不上送** openid、昵称、头像、家庭码、冰箱/账单等任何其他数据。
2. **密钥**：只放云函数环境变量 `DEEPSEEK_API_KEY`（本地写在 gitignored 的 `cloudbaserc.json`，部署时由 tcb 写入云端）；绝不进小程序代码，绝不回传前端。
3. **不记原文**：云函数日志只记耗时与 token 用量（形如 `[reading] ok cost=...ms tokens=...`）。
4. **输出白名单校验**：结构不符（层数/顺序/条数）或命中术数断言词 → 返回失败，前端回退本地解读。
5. **输入提示**：问题框下方常驻「不要填写真实姓名、电话、地址等隐私信息」。
6. **上架边界**：AI 通道属扩展层——`future.*` 与 `zzj-read.js` 被 `packOptions.ignore` 排除，`utils/cloudsync.js` 里的 `readingAI` 用 `EXT:BEGIN/END` 标记在上架构建时剥离。上架包内不存在这条链路。

### 10.4 成本与时延（实测）

| 项 | 实测值 |
| --- | --- |
| 单次耗时 | 约 10 – 12 秒（deepseek-flash 为推理型模型，思考也占 token） |
| token | prompt ≈ 620 / completion ≈ 1700（含 reasoning ≈ 800-1000），合计 ≈ 2300-2600 |
| 输出结构 | 结论 1 + 三层 + 行动 3 + 追问 4 + 收尾 1 |

> 时延较长，所以交互设计成「本地解读先出现，AI 版本再替换」，避免用户干等。
> 若嫌慢，可改用非推理模型或缩短 layers 篇幅（改 `reading.js` 的 SYSTEM_PROMPT）。

### 10.5 后续修订（用户反馈后）

| 问题 | 处理 |
